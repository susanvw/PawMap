# PawMap audit (2026-11-21)

A copy of the audit of what was left to do after Milestone 1, saved from the project thread "Audit app for remaining work".

> **Status since the audit:** the API now runs on Neon Postgres with a Dockerfile, a Render Blueprint (`render.yaml`), Cloudinary photo storage, upload validation (images only, max 10 MB) and per-profile API URLs in `app/eas.json` (merged in PR #6, 2026-11-22). The `development`/`uat` branches are no longer used; all work happens on `main`. The other items below are still open.

Milestone 1 is done. You can report a found pet with a photo, GPS and a comment, and see it on the map. The app type-checks cleanly. There are no TODOs or stubs in the code. The work left is mostly getting it ready to ship, plus the owner side of the product.

## 1. Release blockers

- **The app only talks to your laptop.** `app/config.ts` points to `http://192.168.1.103:5288`. Store builds need a real HTTPS API address set per EAS profile, because release builds block plain http. *(Fixed in PR #6.)*
- **The API isn't deployable yet.** The connection string only exists in user secrets, and the README never says to set it, so a fresh clone crashes on startup. Photos are saved to local disk. There's also no Dockerfile, no hosting and no production config. *(Fixed in PR #6.)*
- **Uploads aren't checked.** Any file type and size is accepted, and the file extension comes from the client and is served back from `/photos`. Someone could upload an HTML file and get it hosted. Coordinates and comment length aren't validated either. *(Fixed in PR #6.)*
- **There's nothing to stop abuse.** No auth, no rate limiting, and no way to delete or moderate reports.
- **App store requirements.** You'll need a privacy policy, since the app uses location and camera and makes GPS points public. The map also loads tiles straight from OpenStreetMap, whose usage policy doesn't allow production apps, so you'll need a tile provider.

## 2. Quality and process

- There are no tests and no CI, only the PR template.
- `development` and `uat` were 7 commits behind `main`. *(Resolved: work now happens only on `main`.)*
- Small stuff: `api/.DS_Store` was committed, and `GET /found-pets` returns every report with no paging or area filter.

## 3. Product gaps (the "reunite" half)

- Owners can't do anything yet: there are no lost-pet reports, no way to contact the finder, and no "reunited" status. `Status` is always "Found".
- There's no filtering by species, date or distance. The map centers on the newest report rather than on you.
- Photos are camera only, with no gallery option.

## Suggested order

API deployment and HTTPS config first, then upload validation, then CI with a few API tests, then syncing the branches. After that, choose the next feature milestone.

## Decision: database

Neon (Postgres) was chosen over MongoDB and SQL Server on 2026-11-21. The API already uses EF Core, which works well with Postgres, and Neon supports PostGIS for "pets near me" searches later.
